# 活动日程

## 模块目标

学生按时间找到可参加的活动，负责人从本人管理日程进入所管理的活动，审核员在授权范围内按版本与审核状态查看；三种角色看到同一份真实安排。

## 功能点

### F1 四种范围与版本

- `public`、`mine`、`managed`、`all` 四种范围共用 `GET /api/v1/timeline`。public 与 mine 只读取获批版本；managed 限本人当前有效成员关系；all 按后台授权。
- mine 以本人有效录取关系为准：录取后出现，退出待处理期间仍保留，退出获批后移出，恢复获批后重新出现。
- 管理范围默认展示工作版本，可切换到获批版本。审核状态筛选按当前工作版本判断，独立于展示版本。
- 普通学生不能通过参数读取工作稿或后台筛选，服务端按 403 拒绝。

### F2 窗口、刻度与两种视图

- 小时、日、周、月四种刻度共用一个日期窗口；列表与时间轴共用同一次查询结果。
- 窗口最长 31 日，超出按契约拒绝。
- 每项活动完整返回窗口内的全部分段，按真实起止时刻绘制；每周规则、排除日与补充时段都要展开。
- 先筛选再按活动分页，total 为活动数；空页也返回统一的 state_evaluated_at。

### F3 审核处理后返回原日程

- 从后台日程选中待审时段进入真实审核页，批准或驳回后返回原日程；窗口、刻度、视图和筛选保持不变。
- 返回时重新读取版本与待审状态：批准后学生端下次刷新显示获批的改期安排，驳回后仍显示原获批安排。
- 原选段在返回后的展示版本里仍存在则保留；已失效则清除并说明原因。批准或驳回改变展示版本后，按新版本重新判定，不跨版本改指到别的时段。
- “只看待审核”下已处理的活动从结果中移出。

### F4 报名与交接改变可见范围

- 学生在本人日程中随录取关系变化增删该活动。
- 负责人被移出单项活动后，即使仍管理其他活动，该活动也从 managed 列表、时间轴和已打开的详情移除。
- 刷新返回 200 但范围已变化时，保留当前窗口与其他仍可见的活动。

### F5 分页期间数据变化后的范围重校准

- 已加载页在新数据下仍须与“变更稳定后同条件的服务端结果”一致：活动 ID、total 与分段逐项一致，列表与时间轴无重复、无漏项。
- 跨页边界变化时重新校准已加载范围，不能只去重留下缺口。
- 侧栏不保留已失效的段。

### F6 深分页刷新的请求上限

- 定时或聚焦刷新限制同时在途的日程请求数，不再对每个已加载页同时发起请求；上限由设计取定。
- 切换条件时停止为旧查询继续补页。
- 同条件临时失败保留已加载结果并可重试；权限收回时清空数据与详情。
- 51 页场景下用请求记录给出实际峰值，原选段恢复与后续加载仍可用。

## 边界

- 不做拖拽改期、拉伸时长或在时间条上直接审批；周期编辑器属其他任务。
- 本批不改 `GET /api/v1/timeline` 的契约与服务端范围语义；分页仍按 activity_code、id 稳定排序。
- #16、#17 的真实业务入口联调不在本批范围：报名退出与活动交接用独立库预置关系验证，两者合入后再联调。
- 活动发现页的服务日期筛选已按获批安排实现，本批不改动。

## 验收

- F1：public 与 mine 的响应不含 has_pending_review、current_review_id；学生带工作版本或后台筛选参数得到 403；mine 随报名状态 accepted → exited → accepted 增删活动。
- F2：四种刻度切换后列表与时间轴内容一致；32 日窗口被拒绝；周规则活动的排除日缺席、补充时段出现。
- F3：从后台日程选段进入真实审核页，批准后返回同一 URL（窗口、刻度、视图、筛选不变），学生端刷新显示新安排；驳回后返回显示原安排；选段在新版本里仍存在则保留，不存在则清除并给出说明；pending=1 下处理后的活动消失。
- F4：预置录取关系后 mine 出现活动，改为 exited 后刷新消失，恢复 accepted 后重新出现；移除负责人的成员关系后刷新，managed 列表、时间轴与详情都不再出现该活动，其他活动保留。
- F5：41 项活动，读第一页后让一项排序靠前的活动移入或移出窗口，加载第二页并刷新；与同条件服务端结果逐项比对无重复漏项；跨页边界变化后校准出完整范围。
- F6：51 页场景触发刷新，请求记录的在途峰值为设计上限；切换筛选后不再为旧查询开始新的取页；同条件失败后可重试成功；原选段与后续加载可用。
