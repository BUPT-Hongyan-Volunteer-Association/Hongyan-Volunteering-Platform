# 活动日程

学生从与「活动发现」并列的「活动日程」查找活动服务日期，负责人从「管理日程」进入自己管理的活动，审核员从「全院日程」进入待审修订。列表和时间轴共用一次查询，选中活动可查看详情，改期在活动编辑页办理，审批在审核页办理。

## 谁能看到哪些安排

四种范围共用 `GET /api/v1/timeline`。服务端在每次读取时重新判断权限与报名关系。[接口契约](../packages/contracts/openapi_v1.2.5.yaml) · [日程查询](../apps/api/src/timeline/timeline.ts)

| 范围 | 活动与展示版本 |
| --- | --- |
| 公开 `public` | 默认显示已发布活动，只展示获批版本。活动发现页的服务日期筛选也按获批安排判断。 |
| 本人 `mine` | 只展示本人已录取活动的获批安排。退出待处理期间仍可见，最后一项录取退出获批后移出，任一项恢复录取后重现。仅此范围提示计划时段重叠。 |
| 本人管理 `managed` | 限具备有效负责人角色且属于当前活动团队的账号，默认工作版本，可切换获批版本。移出单项活动后，刷新会从列表、时间轴和当前详情移除该活动，保留其他可见活动。 |
| 全院 `all` | 按后台授权读取，展示版本同管理日程。两个管理范围的审核状态筛选均看当前工作版本，负责人候选取自授权范围，独立于筛选、窗口和当前页。 |

公开与本人日程省略 `has_pending_review`、`current_review_id`。在这两个范围请求工作稿或按审核状态、负责人筛选会收到 403。各范围的「进行中」按获批活动总起止判断，包含分场之间的间隔，管理端可同时看到工作版本的服务日期和待审标记。

## 服务日期与时间窗口

日程默认展示周一至周日，可切换整月。两个视图均按北京时间每天一格。每项活动只有一条色条，覆盖所选版本从开始到结束的全部服务日期。单日占一格，跨日包含首尾两天。连续服务恰在午夜结束时，最后一天取午夜前一天。周期活动从持续开始日连到持续结束日。接口按半开窗口 `[from, to)` 查找相交活动，最长 31 日。返回完整日期，前端裁剪可见部分。报名截止时刻单独显示在公开日程的报名详情中。[时间窗口](../packages/ui/src/timeline/window.ts) · [甘特图交互](../DESIGN.md#甘特图交互)

首次进入先查当前窗口。若当前窗口为空，日程按同一权限、版本和筛选定位到下一场服务，只有过去活动时定位到最后一个服务日。指定日期、筛选及「今天」保留所选窗口，空状态可直接跳到接口提供的有活动日期。

## 分页与刷新

服务端先限定可见范围和筛选，再在可重复读事务内按活动编号、ID 升序计数和取页。`total` 是活动数，每项返回完整服务起止日期，空页也返回本页的 `state_evaluated_at`。响应头 `X-Timeline-Range` 是全部匹配项的摘要，涵盖活动身份、版本、安排、地点、负责人和展示状态。本人范围另计实际服务时段重叠的活动，请求时刻本身不计入摘要。[活动读取](../apps/api/src/activities/list.ts) · [前端分页](../packages/ui/src/timeline/scheduleRange.ts)

| 页面动作 | 读取与提交规则 |
| --- | --- |
| 首次进入或切换条件 | 从第 1 页读取，每页 20 项。范围、版本、窗口、筛选或页大小变化时立即撤下旧行与详情，旧查询停止领取新页，迟到响应作废。 |
| 加载更多 | 先读下一页。合并前核对摘要、总数、连续页号、页大小、应有行数、活动排序及页级评估时刻。范围收缩时裁掉多余页。 |
| 摘要或页结构变化 | 从首页重读目标范围，整轮通过校验后才替换结果。连续两次不一致，保留上次已核验结果并提示重试。缺少范围摘要时显示读取错误，重试后重新校验目标范围。 |
| 定时刷新或重试 | 页面可见时每 60 秒刷新，聚焦或恢复可见立即刷新。各轮串行，每轮按页号升序领取，最多 3 个请求在途。读取期间收到的刷新合并为一次。普通错误记录最小失败页并保留已有结果，重试从首页重读到目标页。当前查询任一页返回 403 时清空数据与详情，提示权限收回。 |

## 选中活动与审核返回

URL 的 `item` 保存活动 ID。旧小时和日视图链接进入所选日期所在周并沿用原日期、筛选与活动。活动尚未加载时，逐页补读到该活动或最后一页。窗口或筛选改变后，仍在结果中的活动显示最新详情，移出结果则关闭详情并提示。切换可见范围或展示版本会清除选中。[日程页](../packages/ui/src/timeline/SchedulePage.vue)

从日程进入审核，批准或驳回后返回原窗口和筛选。已处理的活动会移出「只看待审核」。审核员也能从日程详情进入该活动的团队页办理交接。[审核页](../apps/admin/src/activities/ReviewPage.vue) · [团队页](../apps/admin/src/activities/TeamDetail.vue)

## 回归用例

接口用例覆盖四种范围、管理字段、版本、31 日边界、周期例外、分页和重叠提示。招募接口用例从真实退出与恢复审批检查本人日程。下表中的交接场景通过独立测试库变更成员关系，验收的是日程刷新后的可见范围。[日程接口用例](../apps/api/test/timeline.test.mjs) · [招募接口用例](../apps/api/test/recruitment.test.mjs) · [日程分页与竞态页面用例](../apps/api/test/timeline-pages.test.mjs) · [三端页面用例](../apps/api/test/pages.test.mjs) · [运行命令](../README.md#开发检查)

| 用例编号 | 需求 | 页面用例标题 |
| --- | --- | --- |
| 日程 1-1 | F3 审核返回 | 审核改期后返回原日程保留条件并重读 |
| 日程 1-2 | F4 报名与交接 | 报名与交接改变可见范围 |
| 日程 1-3 | F5 跨页边界 | 分页期间数据变化后重校准 |
| 日程 1-4 | F6 请求上限 | 深分页刷新请求上限 |
| 日程 1-5 | F6 补页与重试 | 日程分页可重试，详情返回只补读到所选页，候选跨页可用 |
| 日程 1-6 | F6 切换后重试 | 切换筛选时重新聚焦并读取失败，重试仍只显示新条件的结果 |
| 日程 1-7 | F1 范围与版本、F7 条件切换 | 切换展示版本不展示旧稿，权限收回时清空数据和详情 |

| 日程 1-9 | F3 失效链接 | 手机和桌面的旧日程链接进入所在周，窗口外活动保留筛选并关闭详情 |

跨页用例用 41 项活动比较列表、时间轴与服务端的标题顺序、总数和首行活动 ID，样本标题唯一。深分页用例加载 1,001 项共 51 页，记录请求页序与在途峰值。并发失权用例在两页分别注入 503 和 403，验证权限提示优先。
